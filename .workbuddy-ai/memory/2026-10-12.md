## MultiCodexState — 把 MultiGrokState 從 Grok 改寫成 Codex

參考：`https://github.com/goldshoot0720/MultiGrokState`。

### 研究階段（先搞清楚 Codex 的機制，不能照抄 Grok）

用 `gh`/`git clone` 讀完整份 MultiGrokState 後，逐一驗證 Codex 對應的部分：

1. **`~/.codex/auth.json` 是扁平單一物件**，不是 Grok 的 scope-keyed map：
   `{ auth_mode, OPENAI_API_KEY, tokens: { id_token, access_token, refresh_token, account_id }, last_refresh }`。
   → 存檔 = 整檔複製；`switch` = 整檔覆寫（不用 merge）。
2. **JWT 解碼**取得身分：id_token 有 `email` / `name` /
   `https://api.openai.com/auth.chatgpt_plan_type` / `chatgpt_account_id`。
3. **usage 端點**：`GET https://chatgpt.com/backend-api/wham/usage`，
   header 要 `Authorization: Bearer <access_token>` + `ChatGPT-Account-Id: <account_id>`。
   **實測回 200**，payload 含 `plan_type`、`rate_limit.primary_window/secondary_window`
   （`used_percent` / `limit_window_seconds` / `reset_at`(**epoch 秒**) / `reset_after_seconds`）、
   `credits`、`rate_limit_reset_credits`。
4. **refresh 端點**：從 binary 用 `grep -a` 撈出
   `https://auth.openai.com/oauth/token`（另有 `oauth/revoke`），
   client_id `app_EMoamEEZ73f0CkXaXp7hrann`，scope `openid profile email`。
   另外撈到 **`CODEX_REFRESH_TOKEN_URL_OVERRIDE`** —— CLI 自己就認這個環境變數，
   正好拿來當測試注入點。
5. **CLI 指令**：`codex login`（瀏覽器 OAuth）、`codex login status`、`codex logout`。
   binary 在 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`。

### 實作

`bin/cs.js` + `src/{paths,accounts,usage,commands,version,cli}.js` + `test/run.js`，
依賴只有 chalk ^5。指令：`login / logout / switch / list / usage / update / where`。

- 存檔位置 `~/.codex/accounts/<name>_auth.json`（與 codex 共用同一 root）。
- `logout` 依 MultiGrokState 最後定案語意：**先存成 `<email local part>_auth.json`，
  再刪 `auth.json`（含 `.lock`）**；已存在的存檔預設不覆蓋，`-f` 才覆寫。
- `usage` 依 `limit_window_seconds` 命名視窗（5h / weekly / monthly），

- refresh 先試 JSON body，400/415 才退回 form-encoded。

## 移植 Avalonia 桌面 GUI + 補上 CLI 的 `--json`

### 起因

使用者說「開啟本地測試 GUI」。本專案**沒有 GUI**（`D:/CODE` 掃過一輪，唯一的 GUI 是
MultiGrokState 的 Avalonia 版），且本專案 CLI **連 `--json` 都沒有** —— 而
MultiGrokState 的 GUI 正是靠 `list --json` / `usage --json` 呼叫 CLI。
跟使用者確認後選定「移植 Avalonia 桌面 GUI」。

### 1. CLI：新增 `--json`

`src/cli.js`：`list` / `usage` / `where` 都吃 `--json`，新增 `writeJson()` 與
`usageRows()` 兩個 helper。

- **`--json` 時 stdout 只有那份 JSON**：無顏色、無 banner，且 `runCli()` 的
  `wantsNotice` 多一個 `!argv.includes('--json')` 條件 → **背景更新通知不會汙染輸出**。
- `list --json` **刻意不 fan out 成 usage 查詢**（`live = !json && ...`）→ 保持離線、快速。
- `usage --json` 一帳號一列，失敗是 `ok:false` + `error`，**不是少一列**。
- 用 `process.stdout.write` 而非 `console.log`，避免 pretty-print 的 JSON 尾端多一個換行。

### 2. 測試：新增第 11 節（113 → **155 項**）

用 **child process 跑 `bin/multicodexstate.js`**（而不是 import `runCli`）——這是唯一能
抓到「多餘 banner／通知汙染 stdout」的方式。斷言含：無 ANSI escape、stdout 是裸文件、
**`list --json` 完全不碰網路**（`mock.calls.usage === 0`）、`resetAt` 是 epoch ms 等。

### 3. GUI 移植（`gui/MultiCodexStateGui/`）

照 MultiGrokState 的結構逐檔移植（csproj / Program / App / ViewLocator / app.manifest /
Models / Services / ViewModels / Views / `gui/run.cmd`），套件版本原樣沿用
（Avalonia 12.1.4、CommunityToolkit.Mvvm 8.4.2、net8.0）。

**關鍵改寫點（不是照抄）**：

- `CliService`：`MULTICODEXSTATE_CLI` 覆寫、找 `bin/multicodexstate.js`（並 fallback 舊名
  `cs.js`）、設 `CODEX_NO_UPDATE_CHECK=1`。
- **`Models/UsageInfo.cs` 整個換形狀**：Grok 是固定的 weekly/monthly 兩個欄位，
  Codex 是**可變長度的 `windows[]`** → 改成 list，UI 用 `ItemsControl` 綁集合。
- 新增 `ViewModels/WindowViewModel.cs`：一列一個視窗。
  `ResetText` 用 `DateTimeOffset.FromUnixTimeMilliseconds`（epoch ms），
  **不是** MultiGrokState 的 `TryParse(ISO 字串)`。
- `AccountViewModel.ExpiryText` 措辭對齊 `accounts.js` 的 `humanExpiry()`。

### 4. 免費方案 vs plus/pro 相容（使用者明確要求）

- plus/pro = 5h + weekly 兩列；free = 只有一列 30 天（`secondary_window: null`）；
  「完全沒 window」→ `noCapReported: true`，畫 0% 但**顯示說明文字**（≠ 真的 0%）。
- 測試第 11 節把這三種形狀都釘死：free 只有 1 個 window 且 label = `monthly`；
  windowless → `noCapReported: true` 且 `windows.length === 0`。

### 5. 建置與其他

- `.gitignore` 補上 `gui/**/bin/`、`gui/**/obj/`、`gui/**/*.user`（否則會把建置產物推上去）。
- `gui/run.cmd` 用 Node 強制轉 CRLF（**CRLF=16 / bareLF=0**），符合 `*.cmd -text` 紅線。
- `dotnet build -c Release` → **0 警告 0 錯誤**，產出
  `gui/MultiCodexStateGui/bin/Release/net8.0/MultiCodexStateGui.exe`。
- README 新增「Desktop GUI (Avalonia)」與「Machine-readable output」兩節，
  Layout 段落補 `gui/`，測試數量 113 → 155。
