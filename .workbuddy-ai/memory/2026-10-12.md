### 研究階段（先搞清楚 Codex 的機制，不能照抄 Grok）

用 `gh`/`git clone` 讀完整份 MultiGrokState 後，逐一驗證 Codex 對應的部分：

1. **`~/.codex/auth.json` 是扁平單一物件**，不是 Grok 的 scope-keyed map：
   `{ auth_mode, OPENAI_API_KEY, tokens: { id_token, access_token, refresh_token, account_id }, last_refresh }`。
   → 存檔 = 整檔複製；`switch` = 整檔覆寫（不用 merge）。
2. **JWT 解碼**取得身分：id_token 有 `email` / `name` /
   `https://api.openai.com/auth.chatgpt_plan_type` / `chatgpt_account_id`。
3. **usage 端點**：`GET https://chatgpt.com/backend-api/wham/usage`，
   header 要 `Authorization: Bearer <access_token>` + `ChatGPT-Account-Id: <account_id>`。
   **實測回 200**，payload 含 `plan_type`、`rate_limit.primary_window/secondary_window`
   （`used_percent` / `limit_window_seconds` / `reset_at`(**epoch 秒**) / `reset_after_seconds`）、
   `credits`、`rate_limit_reset_credits`。
4. **refresh 端點**：從 binary 用 `grep -a` 撈出
   `https://auth.openai.com/oauth/token`（另有 `oauth/revoke`），
   client_id `app_EMoamEEZ73f0CkXaXp7hrann`，scope `openid profile email`。
   另外撈到 **`CODEX_REFRESH_TOKEN_URL_OVERRIDE`** —— CLI 自己就認這個環境變數，
   正好拿來當測試注入點。
5. **CLI 指令**：`codex login`（瀏覽器 OAuth）、`codex login status`、`codex logout`。
   binary 在 `%LOCALAPPDATA%\Programs\OpenAI\Codex\bin\codex.exe`。

### 實作

`bin/cs.js` + `src/{paths,accounts,usage,commands,version,cli}.js` + `test/run.js`，
依賴只有 chalk ^5。指令：`login / logout / switch / list / usage / update / where`。

- 存檔位置 `~/.codex/accounts/<name>_auth.json`（與 codex 共用同一 root）。
- `logout` 依 MultiGrokState 最後定案語意：**先存成 `<email local part>_auth.json`，
  再刪 `auth.json`（含 `.lock`）**；已存在的存檔預設不覆蓋，`-f` 才覆寫。
- `usage` 依 `limit_window_seconds` 命名視窗（5h / weekly / monthly），
  **不依賴 primary/secondary 位置**（免費方案 secondary 是 null）。
- `parseInstant()` 同時吃 epoch 秒 / 毫秒 / RFC 3339 / 數字字串，壞值回 null。
- refresh 先試 JSON body，400/415 才退回 form-encoded。

### 真實 API 驗證 + 一次需要補救的副作用

對真實帳號跑 `usage` / `list --usage`：**兩個帳號都成功**，印出
`plan free` / `monthly 100.0%` / `Resets: November 8, 02:50, 2026 (in 26d 5h)`。

**但有個副作用要記住**：其中一個帳號的 access_token 已過期，
所以走了 401 → refresh → 200 路徑（**這反而驗證了 refresh 全流程在真實端點上可行**），
OpenAI 端把舊 `refresh_token` rotate 掉了。我測的是**存檔的副本**，
但伺服器端的舊 refresh_token 可能已作廢 → 已把新 tokens 回寫進使用者真實的
`~/.codex/chbondg_icloud_auth.json`（保留 `auth_mode` / `OPENAI_API_KEY` / `last_refresh`）。
**教訓：不要拿真實憑證的副本去測 refresh 路徑。**

### 安裝腳本

仿 MultiGrokState 的 `install.sh` / `install.ps1` / `install.cmd`，
用 sed 做整體改名（MultiGrokState→MultiCodexState、GROK_HOME→CODEX_HOME、
bin/gs.js→bin/cs.js、grok→codex、MG_REEXEC→MC_REEXEC 等）後人工檢查，
確認無殘留 `grok`。

**踩到的坑**：Git Bash 的 `sed` 輸出把 **CRLF 吃成 LF** →
`install.ps1` / `install.cmd` 必須用 Node 事後強制轉回 CRLF
（實測 CRLF=264/178、bareLF=0）。`.gitattributes` 用 `*.cmd -text` 保住 blob 內的 CRLF。
