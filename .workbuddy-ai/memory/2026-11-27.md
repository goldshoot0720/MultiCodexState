## installer 印出版本號 + 日期

三個 installer 都在「來源就緒」後印 `[ok] version 1.1.1 (2026-11-27), 4a215c3`，
結尾摘要再加一行 `Version     : …`。日期取 `git log -1 --format=%cs`（checkout 的
commit date），因為 **main 會一直動但 package.json 不一定升版**，只靠 semver
分不出兩份「1.1.1」。

- `install.sh`：`sed` 讀 package.json、`git -C … log -1 --format=%cs`、`rev-parse --short`。
- `install.ps1`：`ConvertFrom-Json` + `Invoke-InstallerNative git`（沿用既有 helper）。
- `install.cmd`：`!INSTALL_DIR:\=/!` 轉斜線後 `node -p "require('…').version"`；
  日期用 `for /f … --format=%%cs`（batch 內 `%%` 會被降成 `%`，cmd 對沒有結尾 `%` 的 `%cs` 原樣傳給 git）。
- 測試第 13 節釘住三個檔案都要有那兩行 + `%cs`（179 checks）。
- 驗證：`INSTALL_DIR=/tmp/… sh install.sh --no-link` 跑過「全新安裝」與「更新既有」兩條路徑；
  ps1/cmd 在 macOS 沒 pwsh 可跑，只有靜態斷言。commit `8bd6e65`。

## reset credits 沒有到期時間（查證過，別再試）

真實 payload（5 個帳號，全是 team）：
`rate_limit_reset_credits: { available_count, applicable_available_count }` —— **只有計數**。
另外探測 `/backend-api/wham/rate_limit_reset_credits`、`/wham/rate_limits`、
`/backend-api/codex/rate_limits` 全部 404；`?include=reset_credits` 回同一份 summary。
Codex binary 裡確實有 `RateLimitResetCreditDetails`（7 個欄位，含 `reset_type` / `granted_at`）
與 `RateLimitStatusWithResetCredits`，但**沒有可用的 HTTP 端點**能拿到（binary 內連 `wham`
字串都沒有）。→ CLI/GUI 都不可能顯示 credit 的到期日，除非 OpenAI 把它放進 payload。

## 截圖驗證的可用招數（沙箱內）

視窗被 Firefox 蓋住又無法 activate 時，**暫時在 Window 上加 `Topmost="True"`**
→ 編譯 → 覆蓋 bundle 內的 dll → `kill` 舊進程 → `open -n` → 截圖 → 拿掉 Topmost 重編。
`.app` 是 gitignore 的產物，覆蓋 dll 不影響 repo。


## 踩到的工具限制（macOS 沙箱）

- `ps`、`osascript`（System Events / 依 app 名 activate）在沙箱內被拒
  （operation not permitted / -10004 / -1728），**沒辦法把背景開的 GUI 視窗帶到前景**。
  要截圖只能靠 `open -n <bundle>`（LaunchServices 會 activate）。
- `python3` 沒有 Quartz，拿不到 window id，`screencapture -l` 這條路也不通。
